⭐⭐⭐ SHORT ANSWER FIRST ⭐⭐⭐

AuthenticationManager is NOT called at the end.

AuthenticationManager is called INSIDE the Authentication Filter
(UsernamePasswordAuthenticationFilter or your JWT Filter).

Authentication happens BEFORE Authorization.

Authorization depends on the Authentication result.

══════════════════════════════════════════════════════════════════════════════════════════════════════════════

Suppose:

/admin/customers

requires:

ROLE_ADMIN

How can Spring check role?

It first needs:

WHO ARE YOU?

Authentication

then

WHAT ARE YOUR ROLES?

Authorization


Therefore:

Authentication
      │
      ▼
SecurityContextHolder
      │
      ▼
Authorization

ALWAYS

🟪 WHAT IS STORED IN SECURITY CONTEXT?
══════════════════════════════════════════════════════════════════════════════════════════════════════════════

After successful authentication:

Authentication auth =
new UsernamePasswordAuthenticationToken(
        user,
        null,
        authorities);

auth.setAuthenticated(true);


SecurityContextHolder
        .getContext()
        .setAuthentication(auth);


Now SecurityContext contains:

┌───────────────────────────────┐
│ Authentication                │
├───────────────────────────────┤
│ Principal  = john.doe         │
│ Roles      = ROLE_ADMIN       │
│ Auth=true                     │
└───────────────────────────────┘


Later:

AuthorizationFilter

reads the same object.

🏆 INTERVIEW ANSWER
══════════════════════════════════════════════════════════════════════════════════════════════════════════════

AuthenticationManager does NOT execute after all filters.

AuthenticationManager is invoked by an Authentication Filter
(UsernamePasswordAuthenticationFilter, JWT Filter, OAuth2 Filter, etc.)
during filter-chain execution.

If authentication succeeds, an Authentication object is stored in
SecurityContextHolder and the remaining filters continue executing.

Later, AuthorizationFilter reads the Authentication object from
SecurityContextHolder and decides whether the user is allowed to
access the requested resource.

Therefore the sequence is:

Request
→ Security Filters
→ Authentication Filter
→ AuthenticationManager
→ AuthenticationProvider
→ UserDetailsService
→ SecurityContextHolder Population
→ Remaining Filters
→ AuthorizationFilter
→ DispatcherServlet
→ Controller
→ Service
→ Repository
→ Response
