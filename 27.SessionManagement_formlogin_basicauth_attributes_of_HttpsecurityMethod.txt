====================================================================================================
🟦 csrf(csrf -> csrf.csrfTokenRepository(CookieCsrfTokenRepository.withHttpOnlyFalse()))
====================================================================================================

PURPOSE:

Enables CSRF protection and tells Spring WHERE to store the generated CSRF token.

WITHOUT THIS:

POST
PUT
PATCH
DELETE

requests are vulnerable to CSRF attacks.

----------------------------------------------------------------------------------------------------

INTERNAL FLOW

Request
   ↓
CsrfFilter
   ↓
CsrfTokenRepository
   ↓
Generate/Retrieve CSRF Token
   ↓
Validate Token
   ↓
Allow / Reject Request

----------------------------------------------------------------------------------------------------

DEFAULT CONFIGURATION

If you simply write:

.csrf(Customizer.withDefaults())

Spring uses:

HttpSessionCsrfTokenRepository

Storage:

HttpSession
  |
  +---- CSRF Token

Browser cannot directly see the token.

----------------------------------------------------------------------------------------------------

YOUR CONFIGURATION

.csrf(csrf -> csrf.csrfTokenRepository(
      CookieCsrfTokenRepository.withHttpOnlyFalse()))

Storage:

Browser Cookie

Cookie:

XSRF-TOKEN=ABC123XYZ

Now frontend applications can access it.

----------------------------------------------------------------------------------------------------

WHY CookieCsrfTokenRepository?

Perfect for:

✅ Angular
✅ React
✅ Vue
✅ SPA Applications
✅ JavaScript Clients

because:

document.cookie

can access the token.

----------------------------------------------------------------------------------------------------

WHY withHttpOnlyFalse() ?

Default Cookie:

HttpOnly=true

JavaScript cannot read:

document.cookie

for XSRF-TOKEN.

Angular would fail.

Therefore:

CookieCsrfTokenRepository.withHttpOnlyFalse()

creates:

Set-Cookie:
XSRF-TOKEN=ABC123
HttpOnly=false

Now JavaScript can read:

document.cookie

and place token into:

X-XSRF-TOKEN Header

----------------------------------------------------------------------------------------------------

ATTACK PREVENTED

evil.com
    ↓
POST /transfer
    ↓
Browser sends JSESSIONID
    ↓
Attacker cannot read XSRF Token
    ↓
Header missing
    ↓
403 Forbidden

🟥 // .csrf(csrf -> csrf.disable())
====================================================================================================

PURPOSE:

Completely disable CSRF protection.

----------------------------------------------------------------------------------------------------

WHEN USED?

Typical JWT API

http
 .csrf(csrf -> csrf.disable())

because:

JWT APIs are stateless.

Request:

Authorization: Bearer xxxx

Spring does NOT rely on cookies.

CSRF not needed.

----------------------------------------------------------------------------------------------------

WHEN NOT TO DISABLE?

❌ formLogin()
❌ Session Based Authentication
❌ Banking Applications
❌ Browser Applications

Rule:

Session Authentication
         +
Browser
         =
Keep CSRF Enabled

PURPOSE:

Authorization Configuration.

----------------------------------------------------------------------------------------------------

Translation:

Equivalent English:

"Nobody can access anything unless authenticated."

----------------------------------------------------------------------------------------------------

Flow

   ↓

       |
   YES | NO
       |

----------------------------------------------------------------------------------------------------

🎯 ABSOLUTE KEY INTERVIEW TAKEAWAYS
====================================================================================================

✅ csrf() = Enables CSRF protection.
✅ CookieCsrfTokenRepository = Stores token in browser cookie.
✅ withHttpOnlyFalse() = Allows JavaScript to read token.
✅ authorizeHttpRequests() = Defines authorization rules.
✅ anyRequest().authenticated() = All endpoints require login.
✅ authenticationProvider() = Defines authentication strategy.
✅ formLogin() = Login once, session reused.
✅ httpBasic() = Username/password sent every request.
✅ sessionManagement() = Manages session lifecycle, does NOT authenticate.
✅ addFilterAfter() = Insert custom filter into Spring Security chain.
✅ CsrfCookieFilter = Forces CSRF generation and browser cookie creation.
✅ formLogin() + Session + Browser ⇒ Keep CSRF Enabled.
✅ httpBasic() + APIs ⇒ CSRF often disabled.
✅ Session authentication loads user from JSESSIONID.
✅ CSRF validation protects authenticated sessions from forged requests.
✅ XSS can bypass CSRF if attacker executes code inside the trusted origin.
