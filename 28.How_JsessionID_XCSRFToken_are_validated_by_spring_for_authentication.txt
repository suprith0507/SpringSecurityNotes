🎯 INTERVIEW GOLDEN ANSWER
====================================================================================================

✅ JSESSIONID is NOT the user information.
✅ JSESSIONID is merely a key used to lookup a server-side HttpSession.
✅ Spring stores Authentication inside SPRING_SECURITY_CONTEXT within HttpSession.
✅ Session validation occurs through HttpSessionSecurityContextRepository.
✅ Default Session storage is Tomcat JVM memory.
✅ Distributed environments usually store sessions in Redis using Spring Session.
✅ CookieCsrfTokenRepository stores CSRF token inside browser cookie.
✅ CsrfFilter compares XSRF-TOKEN cookie value against X-XSRF-TOKEN header value.
✅ Session validation proves WHO is making the request.
✅ CSRF validation proves the request originated from the trusted application.
✅ Both validations must succeed before protected controllers execute.
