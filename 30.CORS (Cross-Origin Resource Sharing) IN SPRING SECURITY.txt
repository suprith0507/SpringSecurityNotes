🎯 WHAT PROBLEM DOES CORS SOLVE?

Many developers confuse:

✅ CORS
✅ CSRF

They solve completely different problems.

----------------------------------------------------------------------------------------------------

CSRF PROTECTS

evil.com
      ↓
tries to SEND request to bank.com

Question:

"Can this request be trusted?"

----------------------------------------------------------------------------------------------------

CORS PROTECTS

angular-app.com
       ↓
tries to READ response from api.bank.com

Question:

"Should this origin be allowed to access my API?"

🟥 WHAT DOES CORS ACTUALLY DO?
====================================================================================================

"I trust requests coming from these origins."

YES

🟪 SPRING SECURITY CORS CONFIGURATION
====================================================================================================

@Bean
public CorsConfigurationSource corsConfigurationSource() {

    CorsConfiguration config =
            new CorsConfiguration();

    config.setAllowedOrigins(
            List.of(
                    "http://localhost:4200"
            ));

    config.setAllowedMethods(
            List.of(
                    "GET",
                    "POST",
                    "PUT",
                    "DELETE"
            ));

    config.setAllowedHeaders(
            List.of("*")
    );

    config.setAllowCredentials(true);

    UrlBasedCorsConfigurationSource source =
            new UrlBasedCorsConfigurationSource();

    source.registerCorsConfiguration(
            "/**",
            config
    );

    return source;
}

----------------------------------------------------------------------------------------------------

Security Config

@Bean
public SecurityFilterChain securityFilterChain(
        HttpSecurity http)
        throws Exception {

    return http

            .cors(Customizer.withDefaults())

            .csrf(csrf -> csrf
                    .csrfTokenRepository(
                            CookieCsrfTokenRepository
                                    .withHttpOnlyFalse()))

            .authorizeHttpRequests(auth ->
                    auth.anyRequest()
                            .authenticated())

            .formLogin(
                    Customizer.withDefaults())

            .build();
}

🟥 CORS VS CSRF VS XSS
====================================================================================================

CORS

Purpose:

Control who can READ API responses.

Question:

Can Angular read my API?

----------------------------------------------------------------------------------------------------

CSRF

Purpose:

Protect authenticated sessions.

Question:

Did this POST request originate from my app?

----------------------------------------------------------------------------------------------------

XSS

Purpose:

Prevent malicious script execution.

Question:

Can attacker execute JavaScript inside my site?

----------------------------------------------------------------------------------------------------

Example

evil.com
      ↓
tries to read response
      ↓
CORS blocks

----------------------------------------------------------------------------------------------------

evil.com
      ↓
tries forged POST
      ↓

----------------------------------------------------------------------------------------------------

      ↓
XSS succeeded
      ↓
can steal CSRF token
      ↓
can bypass CSRF

🟪 INTERVIEW GOLDEN ANSWER
====================================================================================================

✅ CORS is enforced primarily by the browser.
✅ Spring Security's CORS configuration tells the browser which origins are trusted.
✅ Browser sends Origin header.
✅ Spring's CorsFilter validates the Origin header against CorsConfiguration.
✅ If allowed, Spring returns Access-Control-Allow-Origin.
✅ Browser then allows JavaScript to read the response.
✅ CORS is unrelated to authentication.
✅ CORS is unrelated to CSRF.
✅ CORS should be enabled before authentication/authorization concerns.
✅ Session-based applications usually require:
      CORS
      + Session (JSESSIONID)
      + CSRF
✅ Angular/React applications commonly use:
      withCredentials=true
      + setAllowCredentials(true)
      + Specific Allowed Origins
✅ Never use allowedOrigins("*") together with credentials in production.

🎯 SPRING PROVIDES 3 DIFFERENT WAYS TO CONFIGURE CORS

1️⃣ @CrossOrigin Annotation                  → Controller/Method Level
2️⃣ WebMvcConfigurer                         → Spring MVC Global Level
3️⃣ SecurityFilterChain + CorsConfiguration  → Spring Security Level (Recommended)

IMPORTANT:

All three ultimately add CORS headers.

Difference is:

WHERE the configuration is applied and
WHO processes the request first.

══════════════════════════════════════════════════════════════════════════════════════════════════════
🟦 APPROACH 1 : @CrossOrigin (CONTROLLER LEVEL)
══════════════════════════════════════════════════════════════════════════════════════════════════════

USE CASE

Only a few controllers require CORS.

----------------------------------------------------------------------------------------------------

CONTROLLER LEVEL

@RestController
@RequestMapping("/customers")
@CrossOrigin(
        origins = "http://localhost:4200"
)
public class CustomerController {

    @GetMapping
    public List<Customer> getCustomers() {
        return List.of();
    }
}

----------------------------------------------------------------------------------------------------

METHOD LEVEL

@RestController
@RequestMapping("/customers")
public class CustomerController {

    @GetMapping
    @CrossOrigin(
            origins = "http://localhost:4200"
    )
    public List<Customer> getCustomers() {
        return List.of();
    }
}

----------------------------------------------------------------------------------------------------

FLOW

Angular (4200)
      ↓
GET /customers
      ↓
CustomerController
      ↓
@CrossOrigin
      ↓
Spring Adds

Access-Control-Allow-Origin:
http://localhost:4200

      ↓

Response Allowed

----------------------------------------------------------------------------------------------------

PROS

✅ Simple
✅ Quick
✅ Good for demos
✅ Easy to understand

----------------------------------------------------------------------------------------------------

CONS

❌ Repeated configuration
❌ Difficult to manage
❌ Hundreds of controllers become messy
❌ Not preferred for enterprise projects

══════════════════════════════════════════════════════════════════════════════════════════════════════
🟩 APPROACH 2 : WebMvcConfigurer (SPRING MVC LEVEL)
══════════════════════════════════════════════════════════════════════════════════════════════════════

USE CASE

Application-wide CORS configuration.

----------------------------------------------------------------------------------------------------

@Configuration
public class CorsConfig
        implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(
            CorsRegistry registry) {

        registry.addMapping("/**")
                .allowedOrigins(
                        "http://localhost:4200"
                )
                .allowedMethods(
                        "GET",
                        "POST",
                        "PUT",
                        "DELETE"
                )
                .allowedHeaders("*")
                .allowCredentials(true);
    }
}

----------------------------------------------------------------------------------------------------

FLOW

Angular
      ↓
Request
      ↓
Spring MVC
      ↓
CorsRegistry
      ↓
Check Origin
      ↓
Add CORS Headers
      ↓
Response

----------------------------------------------------------------------------------------------------

PROS

✅ Centralized
✅ Reusable
✅ No repetition
✅ Cleaner than @CrossOrigin

----------------------------------------------------------------------------------------------------

CONS

❌ CORS handled at MVC layer
❌ May conflict with Spring Security
❌ Security filters may block request before reaching MVC
❌ Can cause unexpected 403 issues

🎯 INTERVIEW GOLDEN ANSWER
══════════════════════════════════════════════════════════════════════════════════════════════════════

✅ Spring supports CORS using:
      1. @CrossOrigin
      2. WebMvcConfigurer
      3. SecurityFilterChain + CorsConfigurationSource

✅ @CrossOrigin applies at controller/method level.

✅ WebMvcConfigurer applies globally at Spring MVC level.

✅ SecurityFilterChain-based CORS applies at Spring Security level and is the recommended approach for applications using Spring Security.

✅ CORS is enforced by browsers.

✅ Browser sends Origin header.

✅ Spring validates Origin against configured allowed origins.

✅ If allowed, Spring adds:
      Access-Control-Allow-Origin

✅ Browser then allows JavaScript to read the response.

✅ CORS protects API responses from being read by untrusted origins.

✅ CORS is different from:
      CSRF → protects authenticated sessions
      XSS  → protects against script execution

✅ Real-world Angular/React + Spring Security applications usually use:
      SecurityFilterChain
      + CorsConfigurationSource
      + Session Authentication
      + CSRF Protection
      + allowCredentials(true)
      + withCredentials(true)
