🟦 WHAT IS DelegatingFilterProxy?
══════════════════════════════════════════════════════════════════════════════════════════════════════════════

Tomcat knows only Servlet Filters.

Tomcat DOES NOT KNOW:

SecurityFilterChain
AuthenticationManager
AuthenticationProvider
UserDetailsService

Therefore Spring creates:

DelegatingFilterProxy

Tomcat
  │
  ▼
DelegatingFilterProxy
  │
  ▼
looks for bean

"springSecurityFilterChain"

inside Spring Container.

It acts as a bridge.

Diagram

Tomcat
   │
   ▼
DelegatingFilterProxy
   │
   ▼
springSecurityFilterChain Bean
   │
   ▼
FilterChainProxy


Interview:

DelegatingFilterProxy is a standard Servlet Filter which delegates
actual processing to a Spring-managed bean called springSecurityFilterChain.

🟪 HOW DOES FILTER CHAINING WORK?
══════════════════════════════════════════════════════════════════════════════════════════════════════════════

Filter A
    │
    ▼
filterChain.doFilter()
    │
    ▼
Filter B
    │
    ▼
filterChain.doFilter()
    │
    ▼
Filter C
    │
    ▼
filterChain.doFilter()
    │
    ▼
Controller


If a filter DOES NOT call:

filterChain.doFilter()

chain stops immediately.

Example

JWT Token Invalid

JWT Filter
    │
    ▼
Send 401

NO doFilter()

Controller Never Executes

INTERVIEW ONE-LINER
══════════════════════════════════════════════════════════════════════════════════════════════════════════════

Tomcat → DelegatingFilterProxy → springSecurityFilterChain(FilterChainProxy) →
SecurityFilterChain(ordered filters) → Authentication →
SecurityContextHolder Population → Authorization →
DispatcherServlet → Controller → Service → Repository → Database → Response

Authentication answers "WHO ARE YOU?"
Authorization answers "WHAT ARE YOU ALLOWED TO DO?"
SecurityContextHolder stores the authenticated user for the current request.
