🎬 CHAPTER 2 : WHAT IS A THREAT?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Definition:

🛡️ A threat is anything capable of causing harm to an asset.

Formula:

┌─────────────┐ + ┌─────────────┐ = ┌─────────────┐
│ Asset       │   │ Threat      │   │ Potential   │
│ Valuable    │   │ Danger      │   │ Damage      │
└─────────────┘   └─────────────┘   └─────────────┘

Examples:

╔══════════════════════╦══════════════════════╗
║ ASSET                ║ THREAT               ║
╠══════════════════════╬══════════════════════╣
║ Customer Data        ║ Theft                ║
║ Database             ║ Ransomware           ║
║ API                  ║ DDoS                ║
║ User Accounts        ║ Password Theft       ║
║ Source Code          ║ Insider Leak         ║
║ Money                ║ Fraud                ║
╚══════════════════════╩══════════════════════╝

IMPORTANT:

Threat ≠ Attack

Threat = Possibility
Attack = Actual Action

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🎬 CHAPTER 3 : WHAT IS A VULNERABILITY?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Definition:

🛡️ Vulnerability = Weakness

House Example:

┌──────────────────────┐
│ Front Door Unlocked  │
└──────────────────────┘

Vulnerability.

Application Example:

@GetMapping("/admin/users")
public List<User> getUsers(){
    return userService.getUsers();
}

No Authorization

Vulnerability.

Formula:

┌──────────┐ + ┌──────────────────┐ = ┌────────────────────┐
│ Threat   │   │ Vulnerability    │   │ Exploitable Risk   │
└──────────┘   └──────────────────┘   └────────────────────┘

Threat without vulnerability:
No practical attack.

Vulnerability without threat:
No immediate danger.

Together:
Potential incident.

🎬 CHAPTER 4 : WHAT IS RISK?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Definition:

Risk measures:

"What is the probability and impact of damage?"

Formula:

Risk = Likelihood × Impact

Examples:

╔═══════════════════════════╦═══════════╦═══════════╦══════════╗
║ Scenario                  ║ Likelihood║ Impact    ║ Risk     ║
╠═══════════════════════════╬═══════════╬═══════════╬══════════╣
║ SQL Injection             ║ High      ║ High      ║ High     ║
║ DDoS                      ║ Medium    ║ High      ║ High     ║
║ Typo In Log Message       ║ High      ║ Low       ║ Low      ║
║ Earthquake                ║ Low       ║ Very High ║ Medium   ║
╚═══════════════════════════╩═══════════╩═══════════╩══════════╝

✅ Risk

╚══════╩══════════════════════════════════════════════════════════════╝

Meaning:

S → Pretending To Be Someone Else

T → Modifying Data Illegally

R → Denying Actions Later

I → Leaking Confidential Data

D → Making Systems Unavailable

E → Obtaining Higher Privileges

Use STRIDE As A Checklist:

"What happens if someone spoofed?"
"What happens if someone tampered?"
"What happens if data leaked?"
"What happens if service becomes unavailable?"

🎬 CHAPTER 13 : THE GOLDEN SECURITY MINDSET
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Never Ask:

❌ Can this system be attacked?

Everything can.

Ask:

✅ How difficult is the attack?
✅ How expensive is the attack?
✅ How likely is it?
✅ How quickly can we detect it?
✅ How quickly can we recover?

Security Goal:

Not Impossible To Attack

But

Difficult To Attack
Expensive To Attack
Easy To Detect
Easy To Recover
