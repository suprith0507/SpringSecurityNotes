🟩 STEP 1 : HTTP REQUEST ENTERS TOMCAT

Request:

POST /login

username=admin
password=secret

Tomcat receives request.

Tomcat only understands:

Servlet
Filter
FilterChain

Tomcat DOES NOT know:

AuthenticationManager
UserDetailsService
SecurityContextHolder

Therefore Spring Security needs an entry point.

Flow:

HTTP Request
      │
      ▼
┌────────────────────────────┐

└────────────────────────────┘

🟦 STEP 2 : DELEGATINGFILTERPROXY

Class:

org.springframework.web.filter.DelegatingFilterProxy

Inheritance:

Object
  │
  ▼
GenericFilterBean
  │
  ▼
DelegatingFilterProxy

Purpose:

Bridge Tomcat World ↔ Spring World

Think:

Tomcat Security Receptionist

Simplified Source Code:

public class DelegatingFilterProxy
        implements Filter {

    private Filter delegate;

    @Override
    public void doFilter(
            ServletRequest req,
            ServletResponse res,
            FilterChain chain) {

        delegate.doFilter(req,res,chain);
    }
}

Actual Flow:

HTTP Request
      │
      ▼
DelegatingFilterProxy
      │
      ▼
Spring Security Bean

Responsibilities:

✅ Receive Request
✅ Locate Spring Bean
✅ Forward Request

Does NOT:

❌ Authenticate User
❌ Authorize User

🟦 STEP 4 : SECURITYFILTERCHAIN

Interface:

SecurityFilterChain

Implementation:

DefaultSecurityFilterChain

Created By:

@Bean
public SecurityFilterChain chain(
          HttpSecurity http)
          throws Exception {

      http
         .formLogin()
         .csrf()
         .authorizeHttpRequests();

      return http.build();
}

IMPORTANT:

Most people think this configures security.

Reality:

This BUILDS a SecurityFilterChain object.

Internally:

SecurityFilterChain
           │
           ▼
List<Filter>

Visual:

┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
│ CSRF     │ Login    │ Logout   │ Session  │ JWT      │ Authz    │
│ Filter   │ Filter   │ Filter   │ Filter   │ Filter   │ Filter   │
└──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘

Think:

🎯 SecurityFilterChain = List<Security Filters>

public Authentication
attemptAuthentication(
      HttpServletRequest request){

     String username =
            request.getParameter("username");

     String password =
            request.getParameter("password");

     UsernamePasswordAuthenticationToken token
          = new UsernamePasswordAuthenticationToken(
                 username,
                 password);

     return authenticationManager
                  .authenticate(token);
}

public Authentication authenticate(
                 Authentication auth){

     UserDetails user =
           userDetailsService
             .loadUserByUsername(
                    auth.getName());

     passwordEncoder.matches(
             auth.getCredentials(),
             user.getPassword());

     return authenticatedObject;
}

✅ Calls UserDetailsService
✅ Calls PasswordEncoder

@Service
public class MyUserDetailsService
      implements UserDetailsService {

    @Override
    public UserDetails

       User user =
             repository
               .findByUsername(username);

                 .username(user.getUsername())
                 .password(user.getPassword())
                 .roles("ADMIN")
                 .build();

🎯 ULTIMATE MEMORY FORMULA

DelegatingFilterProxy = Tomcat ↔ Spring Bridge
FilterChainProxy = Security Director
SecurityFilterChain = List Of Filters
UsernamePasswordAuthenticationFilter = Login Request Reader
AuthenticationToken = Login Data Container
AuthenticationManager(ProviderManager) = Coordinator
AuthenticationProvider(DaoAuthenticationProvider) = Login Engine
UserDetailsService = User Loader
UserDetails = User Information Object
PasswordEncoder = Password Verifier
SecurityContextHolder = Logged-In User Storage
AuthorizationFilter = Access Checker
AuthorizationManager = Permission Engine
GrantedAuthority = Permission Model

If you can reproduce the final execution sequence above from memory, you've understood the core of Spring Security better than most developers who use it daily.
