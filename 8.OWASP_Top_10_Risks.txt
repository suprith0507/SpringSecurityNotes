🥇 A01 : BROKEN ACCESS CONTROL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Most Critical OWASP Risk.

Question:

✅ Who are you?
✅ What are you allowed to access?

Application Fails To Enforce Rules.

Architecture:

User
 │
 ▼

Protected Resource

Missing Access Check

 │
 ▼

Unauthorized Access

Examples:

✅ View Other User Records
✅ Access Admin APIs
✅ Download Someone Else's Files
✅ Modify Unauthorized Data

Spring Boot Examples:

❌ Missing @PreAuthorize

❌ Missing Ownership Checks

❌ Missing Role Validation

Bad:

@GetMapping("/admin/users")
public List<User> getUsers(){}

Good:

@PreAuthorize("hasRole('ADMIN')")

Mental Model:

Authentication Says

"Who Are You?"

Authorization Says

"What Are You Allowed To Do?"

Protect Confidential Data.

Example Assets:

✅ Passwords
✅ Tokens
✅ Personal Information
✅ Bank Details

Failures:

❌ Plain Text Passwords
❌ Weak Encryption
❌ Weak TLS
❌ Sensitive Data Exposure

Bad:

stored directly in DB

Good:

BCrypt
Argon2

Used Instead

┌──────────┐
│ Sensitive│
└────┬─────┘
     ▼

🥉 A03 : INJECTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

One Of The Most Famous Risks.

Root Cause:

Application mixes:

✅ User Data

with

✅ Commands

Examples:

✅ SQL Injection
✅ NoSQL Injection
✅ LDAP Injection
✅ OS Command Injection

Concept:

User Input
      │
      ▼
Interpreter
      │
      ▼
Execution

Application cannot distinguish:

Data
or
Command

Spring Protection:

✅ JPA
✅ Prepared Statements
✅ Parameterized Queries
✅ Validation

Mental Model:

Input Must Never Become Executable Instructions.

🎖️ A04 : INSECURE DESIGN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Problem:

Code may be correct.

Design is wrong.

Example:

Bank System Allows:

Transfer Money

without

Second Verification

Code Works Perfectly.

Design Is Insecure.

Difference:

Bug:
Implementation Mistake

Insecure Design:
Architecture Mistake

Architect Responsibility:

✅ Threat Modeling
✅ Security Reviews
✅ Abuse Case Analysis
