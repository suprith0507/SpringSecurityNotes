🟦 THE BIG QUESTION

We never created:

    DaoAuthenticationProvider

So how did Spring Security start using it?

Answer:

Spring Security has a default authentication strategy.

Whenever it finds:

✅ UserDetailsService Bean
✅ PasswordEncoder Bean

it automatically creates:

✅ DaoAuthenticationProvider

behind the scenes.

🟩 CASE 1 : InMemoryUserDetailsManager

YOU WRITE:

@Bean
public UserDetailsService userDetailsService(
        PasswordEncoder passwordEncoder) {

    UserDetails admin =
            User.builder()
                    .username("admin")
                    .password(
                            passwordEncoder.encode(
                                    "admin123"))
                    .roles("ADMIN")
                    .build();

    return new InMemoryUserDetailsManager(
            admin
    );
}

🟦 HOW SPRING KNOWS TO USE DaoAuthenticationProvider

There are many AuthenticationProviders:

┌─────────────────────────────────────────────┐
│ DaoAuthenticationProvider                   │
├─────────────────────────────────────────────┤
│ LdapAuthenticationProvider                  │
├─────────────────────────────────────────────┤
│ JwtAuthenticationProvider                   │
├─────────────────────────────────────────────┤
│ CasAuthenticationProvider                   │
├─────────────────────────────────────────────┤
│ AnonymousAuthenticationProvider             │
└─────────────────────────────────────────────┘

Spring sees:

✔ Username Password Authentication

AND

✔ UserDetailsService

This combination means:

➡ "Use DaoAuthenticationProvider"

because DaoAuthenticationProvider is specifically designed for:

UserDetailsService
        +
PasswordEncoder

authentication.

🟪 HOW IT CHANGES WHEN YOU PROVIDE YOUR OWN DaoAuthenticationProvider

YOU WRITE

@Bean
public AuthenticationProvider

    DaoAuthenticationProvider provider =
            new DaoAuthenticationProvider();

    provider.setUserDetailsService(
            customerService);

    provider.setPasswordEncoder(
            passwordEncoder);

    return provider;
}

.authenticationProvider(
        authenticationProvider())

🟨 INTERVIEW ANSWER

Q. How does Spring select DaoAuthenticationProvider automatically?

Answer:

Spring Security looks for a UserDetailsService bean and a PasswordEncoder bean.
When both are available, Spring automatically creates a DaoAuthenticationProvider and registers it with the AuthenticationManager.
The DaoAuthenticationProvider becomes responsible for loading the user through UserDetailsService and validating passwords through PasswordEncoder.

UserDetailsService + PasswordEncoder
                │
                ▼
Spring Auto Configuration
                │
                ▼
DaoAuthenticationProvider
                │
                ▼
AuthenticationManager
                │
                ▼
SecurityFilterChain
                │
                ▼
Authentication Success

If you add both ways of UserDetailsService then it will show like this.


Found 2 UserDetailsService beans, with names [customerServiceImpl, getCustomInMemoryUserDetails]. Global Authentication Manager will not use a UserDetailsService for username/password login. Consider publishing a single UserDetailsService bean.
